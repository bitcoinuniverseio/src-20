Protocol reference

Specify the
whole event.

This is a strict, portable builder profile for new SRC-20 integrations. It documents the message shape, transaction-derived addresses, state outcomes, and carrier eras without treating historical parser quirks as a recommended wire format.

Authority rule

The maintained Bitcoin Stamps indexer and its release-specific tests decide what that indexer accepts. This page is a carefully conservative integration profile, not a replacement for a pinned indexer version.

Do not infer a universal grammar. Published documents differ on tick characters and legacy number parsing. Use ASCII alphanumeric ticks and plain quoted decimal strings unless you have test vectors for a more permissive case.
Canonical payload schema

Use the smallest valid message.

JSON object key order is not protocol identity, but deterministic compact serialization is safer to inspect and test. New integrations should omit unknown fields and avoid a reliance on permissive parser behavior.

Field Required for Strict builder profile Important interpretation
p All operations String "src-20" Reference implementations case-normalize the protocol identifier. Emit lowercase for portable output.
op All operations String "deploy", "mint", or "transfer" Emit lowercase. Draft extensions are not part of this reference.
tick All operations One to five ASCII alphanumeric characters for broad compatibility Tick identity is case-insensitive. The maintained indexer has a precise allowlist, so do not claim a loose Unicode or emoji rule without an exact release test.
max Deploy Positive plain integer string, no separators or exponent notation Total token cap. Use no value above 18446744073709551615.
lim Deploy Positive plain integer string, no separators or exponent notation Per-mint cap. Historical code may coerce fractions, but new builders must not depend on it.
dec Deploy, optional Integer string from "0" through "18" Defaults to 18 if omitted. It controls the fractional precision used by later amounts.
amt Mint and transfer Positive plain decimal string within the deployed precision Must not exceed uint64 range and must not contain a comma, exponent, or more fractional places than dec.
Optional metadata

Metadata is not an authorization layer.

Current indexer implementations may accept fields such as desc, x, tg, web, and email on a deployment. Treat them as optional indexer metadata, not universal protocol fields.

Not a payload field

Do not put routing into JSON.

Do not rely on from, to, creator, or destination fields. The reference implementation derives ownership and destination from the Bitcoin transaction.

Strict serialization

Numbers are strings on purpose.

Quoted decimal strings avoid JavaScript precision loss and disallow ambiguous scientific notation. Use compact UTF-8 JSON for new output.

Canonical examples

Start with testable payloads.

These examples are deliberately plain. A production builder should validate against the active deployment and current indexer state before it produces a PSBT.

Deploy required fields
{"p":"src-20","op":"deploy","tick":"STAMP","max":"21000000","lim":"1000","dec":"0"}
Mint state-dependent
{"p":"src-20","op":"mint","tick":"STAMP","amt":"1000"}
Transfer state-dependent
{"p":"src-20","op":"transfer","tick":"STAMP","amt":"250"}
Builder normalization Normalize a user-entered tick for lookups, preserve one compact message style, and reject a value that would require a parser to repair it. A wallet should fail early rather than broadcast a transaction that an indexer will not credit.
State transition rules

Balances are an address-indexed ledger.

The value is not a Bitcoin-native UTXO asset. The indexer walks accepted events in chain order, including relevant same-block events, to calculate deployment state, supply, and balances.

Operation Preconditions Indexed result Failure behavior
Deploy Supported carrier, valid message, unused case-normalized tick Creates the token definition with max, lim, and dec. A repeat deployment does not replace the existing ticker definition.
Mint Token exists; message and carrier are valid Credits the minimum of requested amount, per-mint limit, and remaining supply. A mint after supply is exhausted is invalid. A cap is a state result, not a reason to expect a full requested credit.
Transfer Token exists; first-input address has enough indexed balance Debits the source and credits the transaction-derived destination. An insufficient-balance transfer is an invalid SRC-20 transition. It changes neither balance.
Transaction-derived identity

Input zero and output zero carry protocol meaning.

Transaction construction is part of semantic validity. In the reference interpretation, addresses are read from the transaction, then associated with the parsed SRC-20 record.

Source or creator

The first input provides identity.

The address of the previous output spent by vin[0] is the source for a transfer and the creator for a deployment. Reordering inputs can change the interpreted account.

Destination or recipient

The first output provides routing.

The address at vout[0] is the transfer destination and the credited owner for mint. Deployment creator identity comes from vin[0]; the local deploy profile uses output zero only as a sender-dust convention. Sort outputs only if your protocol-aware builder preserves these positions.

PSBT warning A third party can give you a payload that looks correct while its first output or unrelated fee outputs send bitcoin somewhere unintended. Always inspect the entire PSBT, not only the SRC-20 JSON.
Carrier profile by era

Same message, different transport.

For the OLGA/P2WSH profile, the decoded frame is a two-byte length followed by stamp: and UTF-8 JSON. Legacy carriers have their own era-specific parsing paths.

Era Carrier and parser path Builder guidance
Counterparty-era
from 788,041		 Legacy SRC-20 is associated with Counterparty issuance rules and historical parsing requirements. Historical indexer work must use a release-specific parser. Do not produce this format for a modern builder.
Direct Bitcoin legacy
from 793,068		 Published legacy material describes 1-of-3 bare multisig data carriers, keyburn conventions, and ARC4 decoding tied to the first input. Keep ARC4 confined to the era and test vectors that need it. It is not the current universal recipe.
OLGA / P2WSH
from 865,000		 The maintained indexer identifies this as the current SRC-20 carrier. It reconstructs the framed payload from P2WSH data chunks without the legacy ARC4 step. Use a released builder implementation and test it against the target indexer. See the Universe profile for the local integration constraints.
Historical boundary note Direct-Bitcoin SRC-20 begins at block 793,068 in the maintained indexer chronology, while Counterparty SRC-20 is no longer honored after block 796,000. These are successive boundaries, not a single activation height.
Validation outcomes

Classify failure at the right layer.

Clear error language prevents users from thinking that a miner-confirmed transaction necessarily moved a token balance.

Carrier failure

Not a recognized Stamp payload.

The relevant carrier, frame, marker, or JSON cannot be accepted. There is no SRC-20 event to apply.

State failure

Recognized payload, invalid token operation.

The transaction can remain a valid Stamp while the SRC-20 state transition fails, such as an undeployed mint or insufficient-balance transfer.

State success

Recognized payload, accepted token operation.

The compatible indexer updates token definition, supply, or address balance according to the operation rules.
