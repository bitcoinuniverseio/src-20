Bitcoin Universe integration profile

Protocol rules
and product rules.

Bitcoin Universe constructs SRC-20 orders with an OLGA-style P2WSH payload path. This is a documented product profile, not a claim that every SRC-20 indexer accepts every implementation detail. Target-indexer conformance remains required.

Universe order profile

What the local builder does today.

This section documents current implementation behavior in this repository. It is intentionally separate from the general SRC-20 reference so a product detail never becomes accidental protocol folklore.

Area Universe behavior Classification
Carrier Builds a stamp:-prefixed UTF-8 JSON payload into an OLGA-style P2WSH data-output sequence, with a frame before payload chunking. Construction profile. Test against the intended indexer.
Data outputs Uses 32-byte P2WSH chunks with 330-sat data outputs in the current builder. Local implementation parameter, not an SRC-20 token rule.
Output zero Places a dust output for the receiver at vout[0]. Transfer and mint use a supplied receiver when present; deployment defaults to sender dust, while creator identity remains at vin[0]. Designed to align with reference transaction-derived address semantics.
Output order Recipient dust, data outputs, configured service-fee output, then change when applicable. Local transaction layout. Review before every signature.
Order lifetime Unsigned orders expire after one hour. Universe product behavior.
Bulk mint Allows 1 through 10 independent mint transactions through a funding fan-out flow. Universe product behavior. Each resulting transaction still needs independent indexer acceptance.
Conformance is a release gate. The maintained Stamps indexer identifies OLGA/P2WSH SRC-20 as active from block 865,000. Before calling a Universe build profile interoperable, capture a real transaction and target-indexer result for every supported operation.
Local preflight policy

Stricter than historical parser quirks.

Universe validates requests before it creates a PSBT. These checks provide user protection and deterministic UX. They do not override a third-party indexer's protocol implementation.

Ticker

Normalize and validate.

The current implementation trims, validates one to five code points against its configured character policy, and returns an uppercase display value. Use plain ASCII ticks for widest compatibility.

Supply fields

Plain positive integers only.

Universe requires max and lim as positive digit-only strings within uint64 maximum. It intentionally rejects separators and exponents rather than relying on historical coercion.

Amount

Precision is explicit.

The local API accepts a finite positive numeric input and serializes it as a plain decimal string with up to 18 fractional places. Values above JavaScript safe-integer precision are rejected at the builder boundary.

Decimals

Zero through eighteen.

Deployment decimals are optional and must be an integer from 0 through 18. When omitted, the indexer default of 18 is used.

Metadata

Optional and bounded.

Deployment metadata fields desc, x, tg, web, and email are trimmed strings with a current 200-character maximum. They are indexer metadata, not token authorization.

UI compatibility

Do not promise an untested fractional UX.

The protocol can represent precision according to dec, but any client form must validate and display the actual fractional behavior it supports before presenting the flow as available.

Costs and output disclosure

Separate protocol, network, and product costs.

SRC-20 itself does not impose a Bitcoin consensus fee or a universal service fee. A wallet must show the actual transaction costs and any product fee independently, at the exact amount being signed.

Miner fee

Bitcoin network cost

Calculated from the selected fee rate and the actual transaction footprint. It changes with the number of inputs, P2WSH data outputs, change, and any bulk mint flow.

Dust outputs

Carrier and recipient values

The current Universe builder includes an output-zero dust recipient and 330-sat data outputs. These are transaction values, not an SRC-20 token amount.

Universe service fee

Product charge, currently 1,500 sats

At the current repository configuration, a 1,500-sat Universe service fee is added per operation. Bulk mint totals multiply it by the number of mint transactions. Always use the displayed PSBT amount as the final value.

Fee safety rule Do not describe a Universe service fee as a required SRC-20 protocol fee. Do not describe miner fee as a service charge. The signed transaction must show each category separately.
Order lifecycle

Orders are inspectable objects, not opaque requests.

The local API separates creation, signing, broadcasting, and confirmation. A client should preserve the review artifact and report the most specific state it knows.

Create an order.

POST /src20/order validates the request, builds the canonical payload, creates one or more PSBTs, estimates miner and product costs, and returns the review data.

Review and sign in the wallet.

The client verifies inputs and all outputs. It signs only the expected PSBT or ordered bulk PSBT collection before the one-hour order expiry.

Broadcast the signed result.

POST /src20/order/:orderId/broadcast receives one signed PSBT or the complete bulk set, finalizes the transactions, and broadcasts the raw transactions.

Observe status and reconcile external indexing.

GET /src20/order/:orderId exposes the order record. Token list and balance endpoints read indexer data, which should be used to verify the eventual SRC-20 state.

See the API reference for current endpoint shapes and bounds. Treat it as a local implementation interface, not an external standard.

Conformance evidence

What must be true before a release.

Conformance is not a screenshot of a successful broadcast. It is a set of reproducible transactions and observed indexer results tied to a named release and test environment.

  • One deploy, mint, and transfer transaction each built by the released Universe path and accepted by the named target indexer.
  • Evidence that the expected creator, minter, and recipient addresses are derived from vin[0] and vout[0] as intended.
  • Negative vectors for duplicate deploy, undeployed mint, exhausted mint, insufficient-balance transfer, invalid ticker, invalid amount, and wrong-output-zero layout.
  • Output review snapshots showing recipient dust, data outputs, service fee, change, miner fee, and total cost.
  • Reorg or confirmation behavior agreed by the product, including how a pending order is represented before indexer acceptance.
  • Versioned test evidence linked to the Universe release, target indexer release, and network used for the test.
